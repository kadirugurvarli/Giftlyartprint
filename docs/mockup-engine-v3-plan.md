## 2. Principles

1. **Protected pixels.** The customer's artwork/frame pixels are only ever geometrically resampled (a homography warp). They are never regenerated by AI and never recoloured.
2. **AI proposes, geometry decides.** Vision models give coarse corner estimates and classification. Deterministic code refines them, composites, and measures.
3. **Human in the loop.** Any detection below the confidence threshold forces the four-corner editor. The user can always override.
4. **Clean by default.** The mockup master has no text, logo or watermark.
5. **Approval gate.** Social variants and branding are unreachable until a mockup is marked approved.

## 3. Modes

The job type is chosen by what the two inputs contain:

| Mode | Source | Reference | Operation |
|---|---|---|---|
| A: Preserve framed | Already framed | none | Keep frame, mount and artwork. Place into a neutral scene or a plain studio shot. |
| B: Frame artwork | Artwork only | none | Build a frame and mount around the artwork, then place it in a scene. |
| C: Replace art | any | Framed picture in a room | Find the artwork quad inside the reference frame. Warp my artwork in, keep the scene and frame. |
| D: Place on wall | Framed (or framed via B) | Empty wall | Choose a placement quad on the wall. Warp, scale, add shadow and occlusion. |

## 4. Architecture (new files only, under `lib/mockup-v3/` and `app/api/mockup/`)

```
lib/mockup-v3/
  geometry/homography.ts    solve 3x3 H from 4 point pairs (DLT), apply, invert
  geometry/warp.ts          inverse-mapped bilinear warp on raw RGBA, with supersampled edges
  geometry/quad.ts          quad validation (convex, area, aspect), ordering, reprojection error
  analysis/source.ts        is it framed? find frame outer / mount / artwork quads
  analysis/reference.ts     classify: framed-picture vs empty-wall; find target quad(s)
  analysis/refine.ts        snap AI corner guesses to real edges (Sobel plus line fit)
  frame/procedural.ts       moulding and mount renderer for mode B (colour, width, bevel)
  composite/lighting.ts     match scene exposure and white balance to the placed object
  composite/shadow.ts       contact and drop shadow derived from the wall plane
  composite/occlusion.ts    user-painted or model-derived mask for things in front of the wall
  qa/metrics.ts             protected-pixel diff, corner error, edge seam score, tolerance report
  pipeline.ts               orchestration: analyse -> (manual corrections) -> render -> QA
  types.ts                  JobManifest, Quad, Mode, Approval
  social/variants.ts        post-approval only: crop, safe zones, optional branding
app/api/mockup/
  analyse/route.ts          POST fileIds -> mode, quads, confidence
  render/route.ts           POST manifest (incl. manual quads) -> clean mockup fileId + QA report
  approve/route.ts          POST jobId -> flips approval
  variants/route.ts         POST jobId (must be approved) -> social variants with optional branding
app/mockup/page.tsx         upload, analyse, four-corner editor, preview, approve
tests/ ...
```

**Segmentation.** Where a mask is needed (people, furniture or plants overlapping the wall area for occlusion, or irregular frame edges), use a hosted segmentation model behind a small adapter interface (`segment(image, prompt|points) -> mask`), with the user's manual brush as a fallback. Decision needed from you, see section 7.

**Compositing order for C and D:** scene -> contact shadow -> warped object (homography, supersampled edge) -> lighting match (only applied to the *scene-side* layers and the shadow, never to the protected object's colours except an optional global exposure toggle that is off by default) -> occlusion mask over the top.

## 6. Testing strategy

- **Unit:** homography, quad validation, ordering, warp sampling.
- **Property:** protected pixels unchanged under identity placement; warp then inverse-warp returns the original within an epsilon.
- **Visual fixtures:** deterministic synthetic scenes (generated in code, so tests need no private images), compared to committed golden PNGs with `pixelmatch` (threshold and max-diff-pixels fixed per test). Goldens are regenerated only by an explicit `npm run test:update-goldens`.
- **Real-image accuracy tests:** only run when your samples are present locally (`fixtures/private/`, git-ignored). Report corner error versus your hand-marked corners.
- **Gate:** I will not report a phase as done on `tsc`/`next build` alone. I will post test output and the generated images.
- AI calls are mocked in unit tests via the adapter interface; one opt-in live test uses a real key.
